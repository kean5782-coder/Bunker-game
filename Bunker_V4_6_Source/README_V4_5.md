# Бункер V4.5 — Windows EXE и помощник подключения

## Что входит в сборку

`Bunker.exe` — настоящий скомпилированный Windows x64 EXE, а не переименованный BAT. В нём находятся игра V4.4 с изменениями V4.5, исходные изображения и видео, браузерный помощник и большая часть зависимостей. Предназначен для Windows 10/11 x64. Обычные игроки открывают игру в браузере; EXE нужен им только для помощника.

**Существенное ограничение: этот файл не является полностью автономной офлайн-сборкой при первом запуске ведущего.** Windows-интерпретатор Python и три недостающих Windows-компонента не удалось загрузить в среде подготовки. Помощник загружает их при первом запуске ведущего после явного согласия. Нужен доступ к `python.org`, `pypi.org`, `files.pythonhosted.org`. Python и pip самостоятельно устанавливать не нужно; системный Python, PATH и реестр не меняются.

После успешной подготовки в помощнике доступна кнопка **«Собрать автономный ZIP»**. Такой ZIP содержит подготовленное окружение и переносится на другой совместимый Windows-компьютер без повторной загрузки компонентов. Полностью подготовленный ZIP в эту поставку не включён: подготовку необходимо сначала выполнить на Windows. Режим «Я игрок» не требует загрузки Python вообще.

## Первый запуск

1. Распакуйте архив в свою папку. Старый сервер и старые BAT-файлы V4.4 не запускайте одновременно с новой версией.
2. Откройте `Bunker.exe`. Откроется помощник в браузере, а в области уведомлений Windows появится значок.
3. Выберите **«Я ведущий»** или **«Я игрок»**. Сервер запускает только ведущий.
4. Выберите способ подключения. Справа появятся инструкции именно для вашей роли.
5. Ведущий при первом использовании подтверждает загрузку компонентов и нажимает «Подготовить и запустить». После сообщения «Сервер работает» нажимает «Открыть игру» и создаёт комнату.
6. Игрок подключается к ведущему по инструкции и вводит имя. Ссылка из лобби содержит адрес сервера и код комнаты.

Помощник использует отдельный локальный служебный порт. Игровой TCP-порт по умолчанию — **8008**, его можно изменить. «Погружение» и «Неизвестность» по-прежнему выбирает хост в настройках лобби; они не зависят от способа подключения.

## Способы подключения

### Porthole — Local Port Sharing

Ведущий запускает игровой сервер в режиме Porthole, затем открывает Porthole в Steam, создаёт лобби и добавляет TCP-порт игры. Игроки входят в это лобби и подтверждают передаваемый порт. Только после этого открывают адрес игры на своём компьютере, обычно `http://127.0.0.1:8008`.

Игрок не запускает собственный сервер на этом порту. Если Porthole использует у него другой локальный порт, этот порт нужно указать в помощнике или в ссылке. Код лобби Porthole и код комнаты Бункера — разные вещи. Porthole устанавливается и настраивается отдельно; кнопка в Бункере не управляет Steam автоматически.

### Локальная сеть

Устройства находятся в одной доступной друг другу сети Wi-Fi/Ethernet. Ведущий выбирает адрес своего обычного сетевого адаптера и запускает сервер. Игроки открывают его ссылку, например `http://192.168.1.25:8008/?room=ABCD`. Телефону достаточно браузера. Для подготовленного ведущего интернет не требуется. При недоступности проверьте брандмауэр, гостевую сеть и изоляцию устройств.

### Hamachi / Radmin VPN / аналогичные программы

Все участники используют одну выбранную программу и подключаются к одной виртуальной сети. Ведущий выбирает IPv4 виртуального адаптера. Игроки используют виртуальный IPv4 ведущего, а не свой адрес и не адрес обычного Wi-Fi. Программа VPN остаётся включённой во время партии. Её установка, учётные записи и ограничения не управляются Бункером.

### Белый IPv4

Ведущий вводит публичный IPv4 вручную, настраивает TCP-перенаправление на роутере и разрешает нужное входящее соединение в брандмауэре. Внешний порт может отличаться от игрового. Игроки открывают полученную ссылку; на их роутерах перенаправление не нужно. Доступность проверяется из другой сети, а не только на компьютере ведущего.

**Игровая авторизация не перерабатывалась.** Прямой HTTP не шифруется, существующие идентификаторы игроков не являются защищёнными сессиями. Этот вариант предназначен для доверенной компании, не для размещения открытого публичного игрового сервиса. Не отключайте брандмауэр целиком.

## Что делает помощник

Показывает пошаговые инструкции, адреса адаптеров и базовую ссылку, проверяет корректность настроек и занятость порта, запускает и останавливает только свой сервер. Проверка адреса означает лишь доступность HTTP-ответа, не проверку полноценного WebSocket или доступа из интернета. Настройки роутера, Windows Firewall и внешних программ автоматически не изменяются.

При закрытии вкладки сервер продолжает работать. Открыть помощник повторно можно через значок возле часов или повторным запуском того же EXE. Чтобы закончить работу, используйте «Остановить сервер»/«Завершить». **Текущая партия находится в памяти и при остановке сервера теряется.** Автосохранение партии не добавлялось.

Файлы обычной установки находятся в `%LOCALAPPDATA%\Bunker\4.5.0`. Подготовленный переносной комплект использует соседнюю папку `BunkerData`. Журнал доступен в «Диагностика и файлы». Не отправляйте другим людям журналы, предварительно не проверив имена и коды комнаты.

Полная инструкция доступна до подготовки Python и после запуска: **«Инструкция»** в помощнике, **«? Помощь»** в игре. В архиве есть её офлайн-копия `Help/help.html`.

## Что проверено, а что нет

Игра, помощник, обработчики запуска и HTTP/WebSocket проверены в Linux; EXE собран кросс-компиляцией под Windows. **Нативный запуск EXE, значок в трее, загрузка Windows-окружения и его выполнение на Windows здесь не проверены.** Подключения через настоящие Porthole/Hamachi, роутер и публичный IP также не проверены. Подробности — `REPORT_V4_5.md`.

У EXE нет цифровой подписи. Проверяйте источник и SHA-256 из `CHECKSUMS.txt`. Не отключайте антивирус или SmartScreen ради запуска; предупреждение неизвестного издателя само по себе не подтверждает ни безопасность, ни вредоносность.

## Исходники и повторная сборка

В пакете исходников сохранены Go-лаунчер, встроенные ZIP-пакеты, исходники игры и тесты. Для повторной сборки EXE из готовых payload-файлов нужен Go 1.23 или совместимее, Python не нужен. Запустите `BUILD_WINDOWS_EXE.bat` из распакованной папки исходников. Подробности — `BUILD_AND_TEST.md`.

Инструкция Porthole сверена 20 сентября 2026 года с официальными страницами: [Steam](https://store.steampowered.com/app/4963920/Porthole__Local_Port_Sharing/), [сайт разработчика](https://porthole.sestudio.org/). Механизм изолированного Python: [официальная документация](https://docs.python.org/3.13/using/windows.html#the-embeddable-package). Внешние приложения могут изменяться.
