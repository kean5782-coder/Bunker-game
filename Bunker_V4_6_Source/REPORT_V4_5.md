# Отчёт о сборке и проверках Бункера V4.5

Дата: 20 сентября 2026 года. Основа: предоставленный пользователем архив Bunker_V4_4_Immersion_Uncertainty(1).zip.

## Выпущенный EXE

Собран реальный PE32+ Windows x64 GUI executable через Go 1.23.2, GOOS=windows, GOARCH=amd64, CGO_ENABLED=0. Не BAT, не ссылка на внешний установщик и не файл с изменённым расширением. Игра, помощник и чистые Python-зависимости находятся внутри EXE. Python-интерпретатора Windows, pydantic_core, Pillow и Colorama в первоначальном EXE нет: ведущий загружает их после подтверждения в помощнике. Игроку загрузка не нужна.

**Нативное выполнение на Windows не проверено.** Среда подготовки — Linux, Windows/Wine отсутствуют, исходящая загрузка исполняемых пакетов недоступна. Сам факт успешной кросс-компиляции не является проверкой запуска GUI, системного трея, Python или нативных библиотек Windows. Первичная подготовка и перенос автономного ZIP требуют проверки на реальном Windows-компьютере.

## Выполненные проверки

| Проверка | Результат | Границы проверки |
|---|---|---|
| Полный pytest игры | 555 пройдено | Linux, включая 13 новых проверок desktop-интеграции |
| Go unit tests | 13 тестовых функций пройдено | URL/порты, разрешения, ZIP-пути, выбор wheels, SHA, роли, экспорт |
| Игровой интерфейс | 57 проверок пройдено | Реальные HTML/CSS/JS + явная тестовая связка с движком |
| Помощник | 20 проверок пройдено | Реальные ассеты + явный HTTP-мост к тестовому Go-процессу |
| Процесс и сетевой транспорт | 42 проверки пройдено | Реальный Go-процесс, Python-подпроцесс, TCP/HTTP/WebSocket на loopback |
| Изоляция pure-Python зависимостей | Импорты и создание PNG QR пройдены | Python -I -S; нативные pydantic_core/Pillow подставлены для Linux |
| Сохранность медиа | Все 50 файлов совпадают побайтно с V4.4 | SHA-256 изображений, значков и видео |
| Синтаксис JavaScript | Проверен node --check | Приложение, лобби и помощник |

Chromium этой среды запрещает прямую навигацию на localhost. Политика не изменялась. Для проверки интерфейсов использован set_content и явные тестовые соединения; поэтому результаты не обозначены как полная сквозная браузерная проверка Windows. HTTP/WebSocket отдельно проверены через настоящие loopback-соединения, включая получение STATE_UPDATE, PING/PONG и изменение информационного режима хостом.

Проверки LAN/VPN/public подтвердили формирование адресов и работу серверных режимов при обращении через loopback. Реальные подключения второго компьютера, Steam/Porthole, Hamachi/Radmin, провайдерский CGNAT, проброс роутера и доступ с публичного IP **не проверялись**.

Экспорт ZIP проверен unit-тестом с синтетическим окружением: включаются EXE и runtime, исключаются журналы и настройки. Это не проверка исполнения экспортированного Windows-окружения.

## Изменения

- Встроенный помощник с двумя ролями и четырьмя способами подключения.
- Полная офлайн-инструкция в помощнике и кнопка «? Помощь» в игре.
- Windows GUI EXE, открытие браузера, системный трей, изолированная первичная подготовка.
- Отдельный случайный loopback-порт помощника, защищённое управление случайным токеном с проверкой Host/Origin.
- Игрок не запускает сервер и не занимает игровой порт.
- Правильные адреса приглашений; Porthole сохраняет локальный порт компьютера игрока.
- QR на loopback для Porthole не выводится, чтобы не отправлять телефон на его собственный адрес.
- Ручной выбор адаптера, отдельный внешний TCP-порт для белого IPv4.
- Проверка занятости порта и ожидание завершения собственного процесса перед сообщением об остановке.
- Проверка адреса, журнал, повторное открытие действующего помощника, экспорт подготовленного окружения.
- Удалены автоматические обращения за внешним IP при запуске EXE и автоматические изменения правил Windows Firewall.

## Что намеренно не менялось

Игровой протокол, правила, баланс, возрастная механика, информационные режимы V4.4, голосование и пятисекундные результаты. Облачные игровые серверы, автоматическое управление Porthole/Hamachi, новая сетевая авторизация и сохранение партии не добавлялись.

Публичный прямой HTTP не зашифрован. Существующая игровая авторизация не предназначена для враждебной публичной среды. Текущий набор предназначен для доверенных участников. При остановке сервера партия в его памяти теряется.

Исходные результаты находятся в test-results пакета исходников. SHA-256 готового EXE приведён в CHECKSUMS.txt.
